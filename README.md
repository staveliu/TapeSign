# TapeSign · 链上公证处

基于 **TapeOut** 的链上签约、内容公证与双签钱包系统。首页保留双方电子合同：富文本起草、鼠标或触屏手写签名、钱包确认、跨链回签，最后完整归档。链上公证用容器身份声明文字或图片的归属，公开原件或仅存内容哈希，并提供公开查询与分页列表。新增“公证钱包”试验模块：独立交易控制方与容器持有人共同签署绑定、转账及暂停后的恢复，由新建钱包合约强制双签。

客户端可构建为纯静态网站并发布到 TapeOut，也可以保留源码、版本清单、独立客户端和核验工具。即使原业务服务器停止服务，用户仍可通过可用的链节点独立核验。合同流程继续由客户端验证；公证采用缓存先查重、交易提交后立即展示、服务器后台链上核验，并保留手动独立核验入口。

当前应用版本为 0.2.0，合同协议为 **TAPESIGN-2**，公证协议为 **TAPESIGN-NOTARY-1**，支持 X Layer（196）和 BSC（56）。不迁移旧版 TAPESIGN-1 合同。

## 签约与内容公证

| 对比 | 链上签约 | 链上公证 |
| --- | --- | --- |
| 用途 | 记录双方对同一份合同的签署与完整归档 | 记录某个容器对文字或图片的归属声明 |
| 参与者 | 甲乙双方；发起人可以是任意一方 | 一个声明容器，无需对方签署 |
| 输入 | 富文本合同、双方容器 ID、双方手写笔迹 | 一段文字或一张图片、公开方式 |
| 签名方式 | 鼠标 / 触屏手写 + 钱包签名 | 钱包签署内容归属声明，无需画手写签名 |
| 编号 | `TS-…` 合同号；发起、回签、归档按同一编号归并 | `TN-…` 公证号；分块与最终声明属于同一公证 |
| 链上数据 | 完整正文、双方身份、笔迹、钱包签名及前序引用 | 透明模式存原件和哈希；非透明模式仅存哈希及公开声明元数据 |
| 交易流程 | `offer → accept → seal`，正常完整流程共 3 笔业务交易 | 小内容 / 非透明模式 1 笔；较大透明内容为若干分块 + 1 笔声明 |
| 核验方式 | 缓存辅助定位，客户端独立核验后才能继续签约 | 缓存先查重、提交即展示，服务器后台核验，客户端可手动独立核验 |
| 查询入口 | 邀请 / 归档链接、“我的合同” | 内容哈希查询、公证公开列表、公证详情链接 |

第一次使用可直接阅读 [链上签约使用指南](docs/CONTRACTS.md)、[链上公证使用指南](docs/NOTARY.md) 或 [公证钱包使用指南](docs/WALLET.md)。

## 公证钱包（新增试验功能）

资产存放在新部署的双签合约钱包中，交易控制方和 TapeOut 容器持有人分别签名后，合约才允许转出。给原普通钱包公证一条声明不会改变它本来的转账规则。绑定权以合约策略和双签激活事件为准，不由缓存记录的排序决定。

四个入口：创建钱包 #wallet/create、我的钱包 #wallet/wallets、发起转账 #wallet/transfer、共同签署 #wallet/sign。部署确认后自动进入激活签署；两方通过提案链接或 JSON 文件交换签名，支持同链原生币 / ERC20、撤销 nonce、单方紧急暂停和双签恢复。顶部容器选择全站共用。

**链接接力签署**：提案与已有签名以 Base64URL 放在 `#wallet/sign?proposal=…&role=…` 中。接收者打开链接后只读核验并导入，页面显示本次应使用的完整钱包地址；交易控制方签完，将更新后的链接发给公证容器持有人。两方签齐后可直接提交执行，也可把双签链接发回发起方代付手续费。打开链接不会自动连接钱包、签名或发送交易。跨设备分享时需要可公开访问的客户端地址，不能直接使用本机 `127.0.0.1` 链接。

**余额和查询**：显示新公证钱包合约地址的 BNB / OKB 余额、读取区块和时间，支持刷新；RPC 故障显示暂不可用，不显示为零。提供对应链的 OKLink 钱包地址查询入口。“共同签署”页提供“清空当前提案及签名”，只清理当前提案，保留钱包列表、余额、待确认交易和操作历史；没有清空全部钱包记录的入口。详见 [公证钱包指南](docs/WALLET.md)。

~~~sh
npm ci
npm run demo:wallet
~~~

打开 http://127.0.0.1:18743/#wallet/create ，先在本地模拟链完整体验。横幅切换交易方 / 容器方，签名使用明确标注的模拟确认框，**不会打开真实 MetaMask / OKX**。部署、激活及转账仍由本地 EVM 实际执行。正式客户端进入 #wallet/create 后，才使用浏览器钱包和真实容器；仅填写对方地址不能远程唤起其钱包。

本版未独立审计，没有换绑、丢钥恢复、管理员解锁或升级入口。容器 NFT 转走会阻止继续授权，不自动移交签名席位；转回原持有人可恢复资格。请先使用模拟环境，详见 [操作步骤、协议与限制](docs/WALLET.md)。

## 功能

- **共享容器**：在产品顶部从钱包列表选择或手动输入自己的容器 ID；自动处理 .tape 后缀，核验持有人后全站共用。
- **页面锚点**：签约页使用 `#contract/create`、`#contract/open`、`#contract/history`；公证页使用 `#notary/create`、`#notary/search`、`#notary/public`。切换时更新 URL，刷新和浏览器前进/后退恢复相应标签页，保留原交易查询参数。未选容器时右上角红字提示“请先选择容器”。
- **内容公证**：文字或图片、时间关联唯一编号、透明原件上链或非透明哈希上链，钱包签署容器归属声明。
- **公开查询**：本机计算原件哈希，返回匹配的容器与公证记录；公共列表支持搜索、只看我的、时间排序、分页与缩略图。
- **后台核验**：公证发布前缓存查重，提交后标记“RPC 缓存已核验 · 链上未核验”；服务器持久队列核验两条链与同内容冲突，客户端不自动全量扫描，约 10 秒刷新状态。缓存查重只覆盖已收录记录。
- **双方签署**：发起人选择甲方或乙方，输入对方容器 ID，保持原签约流程。
- **富文本与手写**：正文使用受限的结构化富文本；签名框支持鼠标和触屏，笔迹与合同一起被钱包签名绑定。
- **唯一合同号**：UTC 毫秒时间加 128 位随机标识；“我的合同”将发起、回签、归档合并为一份合同。
- **链接定位**：通过 chain 与 tx 参数直接定位交易，无须先扫描全部历史。
- **自动发现回签**：原合同页面和合同列表自动查询后续阶段，不要求对方再次发送回传链接。
- **完整归档**：发起人归档时，一笔 seal 交易包含正文、双方身份、笔迹、钱包签名与前两笔交易引用。
- **独立核验**：两个独立 RPC 槽位核验链上证据；可打印、保存 PDF 或导出 JSON 证据。
- **持久缓存与增量索引**：合同可选缓存加速，公证发布需缓存查重；保存已核验证据并隔离待核验预览，不能仅凭合同缓存预览直接签署或归档。

## 快速开始

需要 Node.js **22.12 或更高版本**、npm、支持 EIP-1193 的浏览器钱包，以及已开通的 TapeOut 容器。发交易需要相应链的原生 gas；仅启动网页和运行单元测试不需要钱包。

~~~sh
git clone https://github.com/staveliu/TapeSign.git
cd TapeSign
npm ci
npm run build
npm run dev
~~~

Windows PowerShell 如果拦截 npm.ps1，可将命令中的 npm 换成 npm.cmd。

- 开发客户端：http://127.0.0.1:18740/
- 构建后的客户端：http://127.0.0.1:18740/dist/index.html
- TapeOut 发布工作台：http://127.0.0.1:18740/publish.html
- 网站订阅激活 / 已有域名付费同步：http://127.0.0.1:18740/activate.html（已上传文件无需重传）

本地服务只监听回环地址。公开网页应部署 dist/ 静态产物，不要把开发服务暴露到互联网。

开源版只包含不带个人密钥的 RPC 地址，默认关闭运营方缓存。公共 RPC 的历史状态支持、可用性与限流可能变化；如果遇到 missing trie node 或 archive token 错误，需配置支持历史读取的节点。配置说明见 [CONFIGURATION](docs/CONFIGURATION.md)。

**自行部署公证功能时，还需配置可用的公证缓存服务。** 当前公证发布流程要求先完成缓存查重；开源版的 `config/app.json` 默认 `cacheOrigin` 为空，未配置时不会跳过查重发交易。按 [部署指南](docs/DEPLOYMENT.md) 启动缓存、设置 HTTPS 地址并重新构建。签约的独立链上核验和公证的手动独立核验仍保留。

## 链上签约

用于双方共同确认同一份合同。顶部先选择当前容器，支持钱包枚举和手动输入；在签约表单中只需补充对方容器、自己的甲乙方角色和正文。双方可以使用不同支持链上的容器，交易由当前操作方的钱包在对应链提交。

### 三个标签页

| 标签页 | 主要操作 | 页面锚点 |
| --- | --- | --- |
| 发起合同 | 填写标题、编辑富文本、指定双方、预览并签署 | `#contract/create` |
| 打开 / 核验 | 粘贴邀请、回签或归档链接，也可输入交易哈希与链 | `#contract/open` |
| 我的合同 | 查询当前容器相关合同、加载更早记录，按合同号合并交易阶段 | `#contract/history` |

### 从起草到归档

1. 发起人连接钱包、选择自己的容器和角色，填写对方容器及富文本正文。
2. 预览并冻结正文，在签名框手写，再由钱包签署 EIP-712 同意消息并发送 offer 交易。
3. 将邀请链接交给对方。交易打包、原文核验成功后即可阅读；达到短确认门槛后开放回签。
4. 对方手写、钱包确认并发送 accept 交易。发起人通过原链接或“我的合同”自动发现回签。
5. 发起人确认双签内容后发送 seal 交易，将完整合同和双方签名归档。
6. 双方查询同一合同号，打开归档、打印或导出证据。

| 阶段 | 由谁操作 | 保存什么 | 接下来做什么 |
| --- | --- | --- | --- |
| 发起 `offer` | 发起方 | 正文、双方身份、合同号、发起方笔迹和钱包同意签名 | 将链接交给另一方，等待回签 |
| 回签 `accept` | 另一方 | 对原合同的引用及另一方的笔迹和钱包同意签名 | 发起方自动发现回签，核验后归档 |
| 归档 `seal` | 原发起方 | 完整合同、双方笔迹、双方钱包签名和前两笔交易定位 | 双方保留链接、原件及核验所需客户端 |

富文本支持加粗、斜体、下划线、标题和列表；手写框支持鼠标或触屏，可撤销一笔或清空。发起前草稿保存在本机。签约仅限双方，当前不提供多人审批或合同附件。

手写图形提供可阅读笔迹，钱包签名绑定其哈希及合同内容。复制公开笔迹无法产生另一份有效的钱包同意签名。容器持有人身份固定在发起时，之后转让容器不会自动转让签约主体。

短确认策略为 X Layer 后续 12 个区块、BSC 后续 24 个区块，并要求两家 RPC 一致且区块头足够新。最终确认单独显示。目标是正常网络下尽快可用，**不承诺一分钟完成或已达到链最终性**。钱包等待、链重组和 RPC 故障都可能延长耗时。

“交易已提交”“缓存预览”“可以继续签署”“最终确认”是不同状态：看到正文不代表可以回签，双签完成也不代表已经归档。原始正文和手写笔迹明文公开上链，JSON 证据导出与打印 / PDF 也不替代重新读取链上证据。详细操作、状态含义及故障处理见 [签约指南](docs/CONTRACTS.md)。

## 链上公证

用于把文字或图片与某个 TapeOut 容器的归属声明关联起来。用户在本机选好内容，签署钱包声明后上链；查询者可以按原件哈希查找相同内容，也可以浏览公开列表。这里的“公证”是产品内的链上声明与证据核验，不表示已经裁定现实中的内容所有权。

### 三个模块

| 模块 | 使用方法 | 页面锚点 |
| --- | --- | --- |
| 内容公证 | 输入文字或选图，选择透明 / 非透明方式，缓存查重后签名提交 | `#notary/create` |
| 内容公开查询 | 输入待查询原文或上传原图；本机计算 SHA-256，只把哈希用于查询 | `#notary/search` |
| 公证公开 | 搜索编号、容器、哈希或公开文字；按时间排序、只看我的、分页浏览 | `#notary/public` |

公开列表每页 12 条。透明图片显示缩略图，透明文字显示前 100 个字符；非透明记录显示元数据，不显示原件。待核验记录的时间是声明时间，链上核验通过后显示区块时间。

### 透明与非透明

| 项目 | 透明公证 | 非透明公证 |
| --- | --- | --- |
| 原件是否上链 | 是，保存原始字节，不压缩图片 | 否，原件留在用户本机 |
| 原件是否发送到缓存 | 可以；内联内容随签名声明提交，分块内容由服务器从链上重建 | 不会 |
| 哈希、编号、容器、签名等元数据 | 公开 | 公开 |
| 支持内容 | 文字；PNG、JPEG、GIF、WebP 图片 | 同左 |
| 原件上限 | 1 MiB | 20 MiB |
| 他人查看 | 可读取完整文字 / 图片并验证 SHA-256 | 持有候选原件的人可计算哈希进行比对 |

非透明模式是**只存哈希及元数据**，不是把加密后的原件托管到链上。原件遗失时，不能从哈希恢复。文字中的空格、换行以及图片重编码都会影响原始字节，查询时应使用原件。

### 发布与后台核验

1. 顶部选好容器，在“内容公证”中输入文字或选择图片。
2. 选择公开方式，勾选归属声明，核对自动生成的公证号、哈希、大小及交易数量。
3. RPC 缓存检查已收录的有效公证及近期待核验记录；发现相同内容或缓存不可用时暂停新提交，保留草稿。
4. 钱包逐笔确认，返回的交易哈希立即保存。透明大图先提交分块，最后还要签名并发送公证声明。
5. 最终声明提交后立即展示，标记 **“RPC 缓存已核验（已收录范围查重通过）· 链上未核验”**。页面不等待全量扫描，不把提交当成最终确认。
6. 服务器通过持久化任务核验交易、容器历史身份、签名、分块与原件哈希；页面约每 10 秒查询状态。
7. 用户可在公开列表查看结果，也可点击“手动独立全链核验”或详情中的“手动独立核验这笔公证”。

**公证编号唯一不等于内容全链排他唯一。** 缓存查重只覆盖已收录记录，两个客户端可能同时通过查重；绕过客户端也可能写入同内容声明。后台发现不同声明使用相同哈希时会标记冲突，不自动裁定谁拥有内容。全量核验的结论也只覆盖列出的链快照。

**分块上传完成不等于公证完成。** 例如原件需要 3 个分块时，共需 3 笔分块交易和 1 笔最终声明；信箱进度“3/3”统计消息，不代表已有 3 份公证。中断后在原浏览器继续同一公证，已知交易不会自动重发。详情见 [公证指南](docs/NOTARY.md)。

## 缓存与性能

公证的透明/非透明模式、原件哈希规则、大小与交易数限制、续传、缓存查重、后台核验和手动独立核验见 [公证说明](docs/NOTARY.md)。公证记录的是归属声明与链上时间，不裁定内容产权，也不等同于法定公证书。

单份邀请、回签、归档分别按引用定位 1、2、3 笔业务交易；每笔仍需读取回执、区块、代码、历史持有人与信箱证据，并非只发 1～3 次 RPC。

“我的合同”首次每个信箱只读取最近 12 条，之后按游标增量读取，旧记录按需加载。可选缓存提供预览、合同归并和后续阶段定位；页面约每 10 秒尝试刷新，实际间隔受请求耗时影响。完整说明见 [合同缓存设计](docs/CACHE-V2.md)，公证的新流程见 [公证说明](docs/NOTARY.md)。

## 独立核验

~~~sh
node scripts/verify.mjs "合同完整链接"
node scripts/verify.mjs "evidence.json"
node scripts/verify.mjs 0x交易哈希 196
~~~

此命令行核验器用于**合同**，从证据文件中提取交易定位后重新读取链上原件，默认要求最终确认。可在末尾加 --proxy，或通过 TAPE_RPC_PROXY 配置本地代理。它不要求原业务网站或缓存服务器在线。公证使用页面中的“手动独立全链核验”或“手动独立核验这笔公证”，详见 [公证指南](docs/NOTARY.md)。

## 范围与信任边界

- 合同仅双方签署；不支持多人审批、合同附件、撤销、作废、修订、合约钱包 ERC-1271 或加密正文。图片公证是独立功能。
- 透明公证原件上限 1 MiB，非透明原件上限 20 MiB；非透明模式只存哈希与公开声明元数据，用户自行保存原件。
- 正文与手写笔迹**明文公开上链**。不要提交不希望公开的个人资料、商业秘密或真实测试材料。
- 正文结构上限 6,500 UTF-8 字节；每份笔迹最多 220 点且不超过 2,300 字节；完整载荷不超过 16,000 字节。
- 两家 RPC 一致不等于链共识证明；旧状态验证依赖归档能力。合同缓存的 verified/ready/status 字段不能直接授权签署或归档；公证缓存的核验状态是服务器报告，不等于客户端独立链上核验。
- TapeOut 站点内容及部分协议可能可更新。版本路径与文件哈希用于核验，不构成链上只读访问控制；应另行保留可信版本清单和客户端副本。
- 本项目未经过独立安全审计。协议核验只证明所实现的技术事实，不提供对签署人现实身份、意思表示或合同法律效力的判断。

详见 [协议](docs/PROTOCOL.md) 与 [SECURITY](SECURITY.md)。
