# 公证钱包（试验版）

公证钱包是 TapeSign 的第三个功能板块。它把交易控制方和 TapeOut 容器持有人的共同授权写进一个新建的钱包合约：绑定、每笔转账和暂停后的恢复，都必须有两份有效签名。

**资产必须存放在这个新合约地址中。** 对原来的普通钱包做一条内容公证，不能改变该钱包的转账规则。本功能没有给普通钱包加代理，也没有自动修改既有公证记录。链上绑定证据是钱包合约的固定策略及 WalletActivated 事件，不依赖按缓存时间排序的声明。

## 四个入口

| 页面 | 操作 | 锚点 |
| --- | --- | --- |
| 创建钱包 | 使用顶部容器，输入独立交易控制地址，部署待激活合约 | #wallet/create |
| 我的钱包 | 本机创建 / 导入列表，按地址与当前容器重新核验 | #wallet/wallets |
| 发起转账 | 查状态、余额，生成绑定 / 转账 / 恢复提案，暂停或撤销序号 | #wallet/transfer |
| 共同签署 | 链接接力或 JSON 导入 / 导出，两方签名、提交执行、清空当前提案 | #wallet/sign |

刷新和浏览器前进 / 后退保留当前标签页。顶部容器沿用全站选择器；支持从钱包查找或手动输入。资金钱包地址、链和签名身份以提案及重新读取的链上策略为准，不能通过改顶部容器替换已绑定的签名人。

## 用链接完成两方签署

激活、转账、恢复提案都提供接力链接。页面根据缺少的签名显示下一方，并列出其完整钱包地址：

1. 尚未取得交易方签名：点击“复制链接，发给交易控制钱包”，发送给该地址的使用者。
2. 对方打开链接，客户端自动核验并导入提案。核对金额、收款地址、网络、容器和有效期后，连接显示的交易控制钱包，点击“交易钱包签名”。账户不符时不能签署。
3. 签署后链接会更新，包含这份签名。点击“复制链接，发给公证容器持有人”，将新链接发给页面显示的容器签名钱包使用者。
4. 容器持有人打开新链接，核对并点击“容器持有人签名”。两方签齐后，可以在当前页面提交执行，或复制“双签执行 / 回传链接”交回发起方代付手续费提交。

也允许容器方先签；指引始终根据尚缺少的签名更新。接收链接无需先选择自己的容器，核验对象来自提案中的容器和合约策略；它不会替换全站已选容器。每份链接是生成时的快照，签完必须复制新链接，对方手里的旧链接不会自动更新。同一提案的已有有效签名会合并；不同提案需要确认替换，不混合签名。

链接格式为 `https://你的客户端地址/#wallet/sign?proposal=<Base64URL>&role=transaction|notary|execute`。提案和已有签名放在 URL 锚点中，不作为网页请求查询参数发给服务器。打开链接只发起只读核验，不请求钱包连接、不自动签名或发交易；有效签名、链上策略、序号与有效期都需核对。核验导入成功后，地址栏收回为 `#wallet/sign`，提案保存在本机，刷新仍保留签署页。失败时原提案保留，支持重新核验链接。

Base64URL 是编码，不是加密。链接可能包含可执行的签名，只交给目标协作方；完整双签允许持有者代为提交同一笔操作，不能修改已签内容。损坏、截断、超长、无效签名、已执行或过期的提案会被拒绝。超过链接上限或聊天软件截断时，仍可使用 JSON 文件交接。

**本机地址不能直接分享给另一台设备。** 如果当前页面在 `127.0.0.1` / `localhost` 上，展开“设置对方可访问的客户端网址”，填入已发布且支持此功能的 TapeSign 客户端地址，再复制链接。网页不会把本机服务自动公开，也不会自动上传提案到缓存服务器。

## 原生币余额与 OKLink

打开、核验或导入公证钱包后，页面独立读取**新合约钱包地址**的原生币余额：BSC 显示 BNB，X Layer 显示 OKB。显示完整精度、网络、读取区块和时间，可以手动刷新；它不是原交易控制钱包的余额，手续费仍由实际提交者支付。切换地址、离开钱包板块会取消旧查询，旧响应不覆盖新地址。查询失败显示“余额暂不可用”，不会显示成零，也不把余额读取作为签名授权。

余额区提供“在 OKLink 查看公证钱包”，并附交易控制钱包、容器签名钱包的查询链接，按链 ID 指向 BSC 或 X Layer 地址页。本地模拟链不生成主网浏览器链接。

打开 http://127.0.0.1:18743/#wallet/create 。黄色横幅表示**独立的本地模拟环境**：

- 使用本机临时 EVM，链 ID 31337；没有真实资产，不连接浏览器中的真实钱包。
- 容器身份和电路 NFT 是测试替身；部署、验签、状态变更和转账在本地 EVM 实际执行。
- 横幅可以切换“容器持有人 / 交易控制方”、填入测试地址及充值测试资产。
- 临时账户每次随机生成，服务重启后链重置；仅此模拟站点的旧钱包记录会在新会话清理。
- 只监听 127.0.0.1，写接口要求同源请求；不要把此模拟服务公开代理到互联网。
- 生产构建不包含模拟入口、测试签名账户或模拟 RPC 替换。开发依赖不随静态客户端打包。

体验顺序：填入测试地址 → 勾选规则 → 部署 → 自动回读并进入双签激活（若节点未同步，点击“核对交易结果”继续）→ 切换为交易控制方并点击“交易钱包签名” → 切换为容器持有人并点击第二签 → 执行 → 核对结果 → 充值测试资产 → 发起转账 → 两方签名 → 执行并核对结果。模拟模式使用明确标注的网页签名确认框，不弹出 MetaMask / OKX。ERC20 测试使用横幅中的 TEST6 地址。

## 使用自己的钱包和容器

正式客户端入口是 http://127.0.0.1:18740/#wallet/create ，构建后也可使用 /dist/index.html#wallet/create。这里的浏览器钱包确认会发送真实链交易，需要 gas。初版尚未独立审计，请优先使用模拟环境；本项目不声称已经完成主网资金安全验收。

### 1. 创建并公证绑定

1. 连接容器持有人钱包，在产品顶部选择自己的 TapeOut 容器。
2. 输入另一个独立保管的“交易控制钱包”地址；不能与容器持有人相同。
3. 阅读试验版说明后，在浏览器钱包批准部署。两者和新钱包限定同一条链：X Layer 196 或 BSC 56。
4. 页面立即保存交易哈希并尝试回读。代码和容器绑定通过核验后加入本机列表；此时仍是未激活状态。如果尚未打包，页面在前台约每 8 秒重试，也可点“立即核对交易结果”，不要重复部署。
5. 部署确认后自动进入“共同签署”，生成新的双签激活提案；也可稍后在“发起转账”生成。交易方和容器方分别核对绑定地址、链、容器、电路编号、有效期和提案指纹，再点击各自的签名按钮。输入对方地址不能远程唤起其钱包，对方需要在自己的页面导入提案并确认签名。
6. 任一愿意支付 gas 的账户提交双签提案；合约验证两方及当前容器持有人，激活并记录 WalletActivated。核对成功后才展示充值地址。

部署和激活各是一笔交易，两次离线签名本身不产生交易。钱包地址加链 ID 是钱包的唯一标识；同一个容器可以绑定多个新钱包，不以公证缓存的记录顺序裁定控制权。

### 2. 给新地址充值

把同链原生币或标准 ERC20 转入页面核验出的**新合约地址**。普通钱包中原有的资产不会自动迁入，也不受此双签机制保护。不要向该地址转入 NFT 或其他本版没有转出接口的资产。gas 通常由执行提案的外部账户支付。

### 3. 每次转账

1. 在“发起转账”选择公证钱包，读取链上状态。
2. 选择原生币或填入 ERC20 合约，填写收款地址、精确金额和有效期。金额按代币最小单位签名，不使用浮点换算。
3. 生成提案，不发送交易。页面显示完整收款地址、资产合约、金额、nonce、有效期、链和钱包地址。
4. 交易控制方签名，复制更新后的链接给容器方；容器方打开核验、签名后，复制双签链接回传。也可使用 JSON 文件，或在同一浏览器切换独立钱包账户。
5. 另一方打开返回链接或导入文件；同一摘要才会合并签名。不同提案不能混合，多余字段或篡改签名会被拒绝。
6. 点击“钱包确认执行”，再次确认当前链状态和两份签名，支付 gas。链上合约自己验证签名后才转账，缓存服务器没有放行权限。
7. 提交后自动检查回执、当前合约状态和对应事件。成功后解除等待并刷新钱包状态；也可点“立即核对交易结果”。成功显示的是“已打包并回读”，不把短时包含说成最终确认。

任何人持有完整有效的双签提案都可代付 gas 提交，但不能改变提案中的收款人或金额。请把链接或导出的文件交给目标协作方；它们没有私钥，但有效签名在过期或撤销前具有执行能力。

## 暂停、撤销与容器转让

- 任一原签名方可以发送 pause 交易暂停钱包，或 cancel 当前 nonce。都需要 gas，并使旧提案序号失效。
- 恢复必须两方重新签署 Resume，不能只凭一方解除暂停。
- nonce 是钱包级单调序号；同一序号的多个提案最多执行一个。重新生成文件本身不会撤销旧签名，必须等待过期或链上撤销。
- 容器 NFT 转让后，当前持有人与创建时记录的签名人不同，绑定 / 转账 / 恢复被阻止。新持有人不会自动取得钱包签名席位。
- 当前实现只比较执行时的 NFT 持有人，不追踪所有转让历史。NFT 回到原持有人后，可再次符合授权条件；转让不是永久撤销。
- 本版没有换绑、丢钥恢复、管理员解锁或升级通道。任何一方丢失签名能力都可能造成资产无法转出；转让容器前应先清空受其约束的钱包。

## 数据与故障恢复

“我的钱包”和当前提案先保存在本浏览器。没有服务器端钱包索引、自动同步或待签通知；换设备可用钱包地址和容器重新导入，也可打开提案接力链接或交换 JSON 文件。链上策略与执行事件可独立读取。

提交前先保存本机操作意图，拿到哈希后立即保存。部署、激活、转账、暂停、恢复和撤销提交后都会自动回读；进入钱包页面或刷新后，也会恢复已知哈希的核对。节点未同步时，页面前台约每 8 秒重试一次，前一请求结束后才开始计时，不并发堆积。离开钱包板块或切到后台会暂停定时重试，返回后继续。

页面顶部直接显示当前步骤和核验阶段（查交易、查回执、核验钱包代码、核验容器），并显示本轮耗时。单轮核验最多 30 秒，超时取消本轮读取并报告卡住阶段，不把超时当成功，也不删除待确认记录。缺少哈希时明确显示“没有进行自动查链”，不会只显示“正在核对”。“复制排查信息”仅包含页面路径、链、交易哈希、容器、阶段与错误，不包含交易 calldata、签名或私钥。

创建页面的第一次钱包弹窗用于**部署新钱包合约**。部署交易核验完成后，才会生成双签绑定提案；此时切换到输入的交易控制方账户，点击“交易钱包签名”，再由容器持有人签第二次。仅输入钱包地址不会远程唤起该钱包，也不会让原普通钱包自动变成双签账户。

待确认时禁用部署、执行、暂停等发送按钮，避免重复提交。看到等待不代表还需重新签名。回执、事件与钱包策略通过核验后才清除待确认记录；明确失败的交易会记录失败并解除等待。查询失败、缺失回执或错配哈希都不能清除记录。

钱包返回结果未知且没有交易哈希时，不自动重发也不自动清空。从钱包活动复制原交易哈希，填入“原交易 / 替换交易哈希”后点击“立即核对交易结果”。加速后可以使用输入内容相同的替换交易；真正取消为不同输入的交易，本版不自动判断。

如果只想放弃当前提案，在“共同签署”标签页点击 **“清空当前提案及签名”**。只删除本机当前提案、该提案的签名、导入文本和接力链接；钱包列表、余额、待确认交易、操作历史、合同、公证和容器选择全部保留。按钮不出现在创建、钱包列表或转账页，也没有清空全部钱包记录的入口。清空后仍停留在共同签署页，可以导入或生成新提案。

同一浏览器的其他标签页会同步清空旧提案视图，迟到的旧导入或签名结果不会重新写回。待确认交易继续核对，已部署的钱包仍可查询；清空之前已提交的部署在稍后确认时不会自动重新生成提案，需要时可在“发起转账”手动生成双签激活提案。

清空提案不是链上撤销：已提交的交易仍可能执行，已经分享给他人的有效签名也不会失效。需要撤销链上授权时，应使用已有的“撤销当前序号”操作。清空按钮自身不发送交易，也不会转出或删除资产。

本版读取固定快照下的 walletState，一次调用读取九个策略 / 状态字段，避免逐字段请求。身份、代码、nonce 和持有人仍需读取链上最新状态，不能只使用历史缓存；不进行全量交易历史扫描。服务故障会阻止新签署 / 发送，不会把失败当作授权成功。

## 合约与签名协议

- 源码 contracts/TapeNotaryWallet.sol；编译 solc 0.8.30、Shanghai、optimizer 200；依赖 OpenZeppelin Contracts 5.2.0。
- EIP-712 域：TapeSign Notary Wallet，version 1，当前 chainId 和 verifyingContract。
- Bind：电路地址及 tokenId、容器地址、两个签名人、nonce、deadline、policyVersion。
- Transfer：asset（零地址表示原生币）、recipient、amount、nonce、deadline、policyVersion。
- Resume：nonce、deadline、policyVersion。
- 合约允许签名最长有效期 7 天；页面默认 30 分钟，可选 1–1440 分钟。
- 重放保护由合约 nonce、截止时间和签名域共同实现。EIP-712 标准本身不自动实现重放保护。
- 合约支持 EOA 或 ERC-1271 签名人；本版按钮针对浏览器 EOA 签名流程。外部智能钱包可生成自己的有效 ERC-1271 签名后通过提案导入，不提供 Safe 等专用签名适配。
- 执行前验证 container.token() 的同链电路元组及 NFT ownerOf，验签和 nonce 更新在转账合约中完成。
- 客户端钉住完整运行时代码哈希，并沿用 TapeOut 身份核验。不凭名字相似或一个自称容器的任意合约放行。
- Solidity 构造器接受 NFT / 容器地址参数并核对其元组，不内置 TapeOut 官方地址注册表；任意人也可以为其他 NFT 部署同代码。因此单看运行时代码不足以证明官方容器身份，必须同时核验策略和真实 TapeOut 身份。
- 无代理、升级、delegatecall、任意调用、ERC20 approve / permit、插件、跨链执行、NFT 转出、委托签名钥匙或平台恢复后门。
- 标准 ERC20 调用使用 SafeERC20；有手续费、重基、冻结或恶意逻辑的代币可能与面额不同，页面不保证实际到账数量。两份签名不消除恶意代币、钓鱼诱签或两把密钥同时失陷的风险。

标准参考：EIP-712 Typed structured data hashing and signing、ERC-1271 Standard Signature Validation Method for Contracts、ERC-6551 Non-fungible Token Bound Accounts（eips.ethereum.org）。
