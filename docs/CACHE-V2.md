# V2 合同索引与永久缓存

本篇描述链上签约的缓存与索引。内容公证的发布前查重、签名预览和服务器后台核验使用同一服务中的独立模块，见 [公证指南](NOTARY.md)。

合同编号由 UTC 毫秒时间与随机标识构成，并由文档签名覆盖。界面按编号归并 offer、accept、seal，同号异指纹显示冲突。V1 不迁移。

缓存为可选 Node.js 服务，开源版不含共享运营方地址。默认 127.0.0.1:18741，经 HTTPS 反向代理公开。见 [部署](DEPLOYMENT.md) 和 [配置](CONFIGURATION.md)。

## API

路径相对服务根目录，代理可添加 /tapesign 前缀。

| 方法/路径 | 用途 |
| --- | --- |
| GET /contracts?container=<id> | 容器相关合同，按编号归并 |
| GET /transaction/<chain>/<tx> | 已核验交易记录 |
| GET /latest/<chain>/<tx> | 同正文、offer 及兼容 acceptance 分支的后续阶段 |
| POST /notify | 只提交 {"chainId":"196","tx":"0x…"} 定位入队 |
| GET /health | 游标、监控、队列和错误 |

chainId 是字符串 196/56；tx 是小写 0x 加 64 位十六进制。notify 的 202 只代表入队，不是已确认/验证。无效请求 400，过大正文 413，限流 429。没有签名私钥或登录状态。

## 存储和同步

SHA-256 键的 JSON 对象与原子替换存储合同交易、独立 RPC 槽位数据、队列、监控、游标；无需外部数据库。默认 /var/lib/tapesign-cache，可用 TAPESIGN_CACHE_DIR 改写，备份整个目录。

提交交易后通知后台。核验队列、信箱增量监控与区块扫描独立调度。客户端也定期查相关链的容器信箱，首次每个信箱最近 12 条，后续按游标读取。

页面/列表约每 10 秒尝试刷新，实际间隔受请求耗时影响。原链接自动发现回签，回传链接为备用。首次后台扫描不重放全链历史；已知旧交易可明确通知补入。

health.contracts 是缓存交易数，不是界面唯一合同数。失败任务有界退避，重启可重试待处理任务。

## 信任边界

客户端核验缓存正文指纹、签名和引用后才显示缓存预览；服务器 ready/finalized/status 不能授权签署、归档或导出。完整证据仍经两个独立 RPC 槽位核验。

RPC 对象按槽位隔离，只复用已最终确认、固定高度数据，不复用空回执、最新状态或区块头。合同永久保留，RPC 对象复用有效期为一小时。

单节点范围日志只发现候选哈希，每笔候选仍需双节点完整核验才进入可查询合同。伪造日志不能制造有效合同。

各 RPC 方法与单区块/范围日志故障冷却隔离；全部冷却时尝试最早失败者。空回执尝试同槽位备用，缺失和错误不转为成功，非空分歧仍拒绝。历史状态需要具备相应归档能力的节点。

## 测试

npm test 覆盖存储、后续发现、重复归并、分支冲突、单节点伪造发现。test:cache-ui 覆盖原链接自动追踪、缓存/链核验分离、刷新保留笔迹和页面切换竞态。

node scripts/check-cache-live.mjs <offerTx> [--bsc] 对明确提供且已双签/归档的合同执行只读浏览器检查，不发送交易。含真实数据的报告和截图写入 .local/，不得提交。
