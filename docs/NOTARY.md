# 链上公证使用指南

TapeSign 链上公证处包含链上签约与链上公证。签约保留原双方流程。顶部容器供全站使用，可从钱包列表选择，也可手动输入短 ID 或带 ".tape" 的 ID。手动输入跳过枚举，但仍核验钱包、绑定及持有人。切换钱包后重新选择。

链上公证用于记录“这个内容属于我的 TapeOut 容器”的单方声明，不需要另一方回签，也不需要手写签名。双方共同签署合同，请阅读 [链上签约指南](CONTRACTS.md)。当前支持 X Layer（196）与 BSC（56），公证在所选容器所属链发送。

## 三个模块

| 模块 | 操作与结果 | URL 锚点 |
| --- | --- | --- |
| 内容公证 | 输入文字或选择 PNG、JPEG、GIF、WebP 原图，选择公开方式并签署归属声明 | `#notary/create` |
| 内容公开查询 | 在本机计算原件 SHA-256，按哈希查询对应容器、声明及核验状态 | `#notary/search` |
| 公证公开 | 搜索编号、容器、哈希、透明文字，按时间排序、只看我的公证、分页浏览 | `#notary/public` |

切换标签页会更新 URL 锚点，刷新或浏览器前进 / 后退会恢复对应模块。没有选择容器时，产品右上角红字提示“请先选择容器”；发布和“只看我的公证”使用顶部的当前容器。

## 透明与非透明如何选择

透明公证保存完整原始字节、SHA-256、容器身份与钱包签名；非透明公证仅保存哈希和声明元数据，原件不上传服务器或区块链。两者都公开编号、容器、持有人、类型、大小和时间。文字按 UTF-8 原样计算，图片不压缩、不重编码。透明最大 1 MiB，非透明最大 20 MiB。

| 对比 | 透明公证 | 非透明公证 |
| --- | --- | --- |
| 原文 / 原图 | 完整公开上链，较大原件分块保存 | 保留在用户本机，不发送到链上或缓存 |
| 编号、哈希、容器、钱包签名及声明元数据 | 公开 | 公开 |
| 列表与详情 | 原件可用且哈希匹配时，显示缩略图 / 文字预览及完整内容 | 仅显示公开元数据，不提供原件预览 |
| 后续比对 | 从公开原件重算 SHA-256 | 原件持有人提供同一文件或文字，在本机重算 SHA-256 |
| 原件大小上限 | 1 MiB，即 1,048,576 字节 | 20 MiB，即 20,971,520 字节 |
| 交易数 | 小内容 1 笔；较大内容为分块交易加 1 笔最终声明 | 1 笔最终声明 |

非透明模式不是加密原件托管，不能从哈希还原遗失文件；知道候选原文或原图的人仍能计算哈希比对。文字空格、换行、编码变化，以及图片压缩、裁剪、格式转换或元数据变化都可能改变哈希。查询应使用同一原件，不做相似图片识别或语义相似查询。不支持 SVG。

产品记录容器持有人的内容归属声明与链上时间，不裁定著作权，也不是法定机关出具的公证书。

## 操作指南

### 发布一份公证

1. 连接浏览器钱包，在顶部选择自己的容器；钱包应具备该链所需 gas。
2. 打开“内容公证”，选择文字或图片。文字粘贴到输入框，图片选择原始文件。
3. 选择透明或非透明方式，勾选容器归属声明，点击“核对内容并公证”。查看计划中的 `TN-…` 公证号、SHA-256、大小和所需交易数；操作过程中留意钱包逐笔确认。
4. 客户端先请求 RPC 缓存查重。已发现有效重复、待核验冲突、缓存不可用或响应无效时暂停新交易，保留当前草稿。
5. 透明大内容先发送分块；最终签署 EIP-712 归属声明并发送公证交易。非透明或内联小内容直接进入最终声明。所有交易由用户钱包确认并支付 gas。
6. 最终交易返回哈希后，页面立即展示签名预览和“RPC 缓存已核验（已收录范围查重通过）· 链上未核验”，链上核验交给服务器后台继续。
7. 保存详情里的“公证查询链接”。之后从“公证公开”搜索编号或勾选“只看我的公证”查看进展，无需重新发布。

公证号由 UTC 毫秒时间和 128 位随机标识生成并写入声明。同一公证的分块与最终声明使用同一编号。该编号便于区分记录，不代表内容已经获得全链唯一登记；链上时间与客户端生成编号的时间也不是同一概念。

### 查询一段文字或一张图片

1. 打开“内容公开查询”，选择文字或图片，输入原文或选择原图。
2. 点击“计算哈希并查询”。SHA-256 在本机计算，查询原件不会上传到缓存，只发送哈希作为查询条件。
3. 查看匹配声明的容器、编号、链、时间及核验状态；同一哈希可能对应多条声明，应逐条核对。
4. 缓存没有结果，只能说明尚未收录匹配记录。需要进一步比对时，使用“手动独立全链核验”；未完成扫描时不能得出全链不存在的结论。

透明与非透明声明都可按同一原件哈希查询。查询非透明声明时，不会因此公开查询者提供的原件。

### 浏览公开列表

“公证公开”支持编号、容器 ID、哈希或公开文字搜索，最新 / 最早在前，每页 12 条。勾选“只看我的公证”按顶部容器筛选；列表覆盖当前缓存已收录的记录，扫描状态同时显示两条支持链的处理进度。

透明图片显示缩略图，透明文字显示前 100 个字符，点击“查看公证详情”读取完整信息。分块原件尚未回读完成时可能暂时没有预览；非透明记录始终不显示原件。原件完整且哈希匹配时，详情提供“保存哈希匹配的原件”。

待核验预览使用声明时间，明确标注尚未链上核验；取得链上证据后使用区块时间。详情中的核验来源可区分“签名声明预览”“服务器报告”和“客户端独立核验”。

## 核验状态怎么读

| 页面状态 | 实际含义 |
| --- | --- |
| RPC 缓存已核验 · 链上未核验 | 已收录范围查重通过，签名声明可预览；交易是否打包、历史身份及完整链上证据仍待核验 |
| 链上未核验 · 后台重试中 | RPC、回执或分块暂时不可用，后台保留任务并重试，不要求重复付款 |
| 服务器链上核验通过 · 待最终确认 | 服务器已核验证据，但还未达到最终确认条件 |
| 服务器链上核验通过 · 最终确认 | 服务器报告链上证据与最终确认检查通过；仍应注意核验来源 |
| 客户端独立核验通过 | 用户主动发起独立链上读取并完成核验；确认程度另行显示 |
| 已扫描范围未发现重复 | 仅对报告中的两条链快照和已完成扫描范围成立，不是永久排他保证 |
| 唯一性冲突 | 发现相同内容的其他公证，需要核对各声明；不会自动裁定内容归属 |
| 链上核验异常 / 交易与缓存声明不一致 | 证据无效或不一致，应核对交易和原件，不能把预览当作成功公证 |

签名检查、链上收录、最终确认和内容查重是不同维度。单笔核验通过不代表全量查重完成，服务器报告也不等于当前浏览器已经独立读取链上数据。

## 缓存优先发布（2026-09-28）

1. 本机计算哈希，缓存服务立即查询已收录的有效记录及近期待核验声明。缓存已发现有效重复或待核验冲突时暂停新的提交；缓存不可用、响应过期时保留原草稿，不显示查重通过。
2. 缓存查重通过后，核验当前容器持有人并请求钱包签名、发交易。每笔返回的哈希立即保存，不在图片每个分块之后等待回执或重放全链。
3. 最终声明交易返回哈希后立即展示本地签名预览，并标注 **RPC 缓存已核验（已收录范围查重通过）· 链上未核验**。这不代表交易已经打包或最终确认。
4. 签名声明与交易定位写入本机待通知列表，并通知服务器。服务器持久化后，即使关闭网页仍继续核验。通知失败时刷新页面仍会重试；浏览器关闭前未送达的任务，需要再次打开客户端才能重试通知，也可能被服务器信箱扫描发现。
5. 服务器后台核验交易、回执、合约、历史容器身份、签名、所有分块和原件 SHA-256。页面每约 10 秒轻量查询状态，失败后继续重试，不锁定表单。
6. 后台分别显示：链上待核验、重试、证据异常、已核验待最终确认、最终确认、同内容冲突。两条链在有效快照均完整扫描后才能报告“已扫描范围未发现重复”；此结论带快照和时效，不是未来永久唯一的保证。

缓存是加速层，缓存查重仅覆盖已收录记录，不是区块链全局排他锁。两个客户端可能同时查重通过并广播，用户也可以绕过客户端直接发送消息。服务器发现同哈希不同声明后会对双方标记冲突，不会删除链上交易、自动重发或自动裁定内容所有权。严格的全链排他唯一性需要链上协议提供原子占位机制，本版未增加此机制。

### 页面性能与独立核验

正常打开页面、发布、查询、翻页和刷新均不会启动客户端全链扫描。服务器承担完整公共信箱扫描及待核验任务，独立队列防止扫描阻塞通知；慢任务有超时、退避重试，队列在服务重启后恢复。

保留“手动独立全链核验”及详情内“手动独立核验这笔公证”，供用户直接从链验证、在缓存不可用时核查证据。全链手动核验可以停止，2 分钟超时；单笔独立核验 1 分钟超时。后台照常工作。服务器核验状态始终标为服务器报告，客户端仅本地检查签名与可用内容的哈希，不冒充独立链上验证。

这项变更减少用户等待核验的时间，不能加快区块生成、钱包确认或保证链上最终确认在一分钟内完成。

### 分块与恢复

透明内容不超过 9,000 字节时采用内联编码；最终消息仍受包含元数据、签名和编码开销在内的 16,000 字节上限约束，不能仅凭原件大小保证发送成功。更大原件按 9,000 字节分块，每块独立交易，最后一笔声明引用全部分块，最终声明本身也需满足载荷上限。分块不单独列成公证。钱包正常返回哈希后继续下一步，所有分块的链上证明统一后台核验；失败 / 缺失分块不会被当成有效完整公证。

例如原件需要 3 个分块时，总共需要 **3 笔分块交易 + 1 笔最终声明**。扫描提示“已核对 3/3 条信箱消息”只统计消息，其中可能全部是分块，并不表示已经有 3 份完整公证。

刷新后保留同一编号、分块交易及未知结果。已返回哈希的旧版待核验分块可直接恢复提交进度，显示“已提交”而非“已核验”。钱包未返回哈希时仍阻止重发，用户从钱包活动粘贴哈希后，通过单笔链上匹配恢复。未发送草稿可取消，已发送交易不自动丢弃或重复支付。

待核验预览只有声明时间，明确标为未经链上验证；服务器核验成功后使用区块时间。只有完整原件哈希匹配才显示图片 / 文字和原件保存入口；非透明记录不含原件。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 分块全部提交了，公开列表却没有公证 | 返回原浏览器的“内容公证”，点击“继续提交公证”；还需钱包签署并发送最后一笔声明 |
| 长时间显示“链上未核验” | 查看交易是否已打包及后台重试状态；保留哈希等待，必要时手动独立核验，不重新发布同一内容 |
| 缓存查重通过，后来却出现冲突 | 查重只覆盖当时已收录记录，可能存在索引延迟或并发提交；查看冲突记录和链上时间 |
| 同一张图查询不到 | 确认使用原文件；截图、压缩、导出或改动元数据都可能改变字节与哈希 |
| 非透明原件丢失 | 链上只有哈希和元数据，无法恢复原件；发布前自行保存原文 / 原图 |
| 钱包没有返回交易哈希 | 从钱包活动复制哈希，使用“核对并恢复”；恢复会检查单笔链上匹配，不盲目重发 |
| 自行部署后提示缓存查重不可用 | 配置可用的 `cacheOrigin` 并重建客户端，检查 HTTPS、服务健康和请求限制；本版不跳过缓存查重发布 |
| 换浏览器后没有未完成草稿 | 提交进度保存在原浏览器，应先回原浏览器恢复并核对钱包活动，避免另开一份重复公证 |

部署步骤见 [部署指南](DEPLOYMENT.md)，节点与缓存地址见 [配置说明](CONFIGURATION.md)。以下为开发者协议与服务接口。

## 协议

- 协议 TAPESIGN-NOTARY-1，前缀 0x544e0100；原合同仍为 TAPESIGN-2。
- 编号 TN-<17 位 UTC 毫秒时间>-<128 位随机后缀>；客户端时间不是可信时间证明。
- notarize 含 claim 与 EIP-712 签名，绑定 claim 哈希、原件哈希、容器及归属声明。
- chunk 含编号、身份、哈希、索引、总数和 base64 原始分块；单笔消息不超过 16,000 字节。
- 公共信箱是 endpoint('196', last20Bytes(keccak256(UTF8('TAPESIGN-NOTARY-1:public-index'))))。X Layer 和 BSC 各自 DeWebHub 的本地 inbox 分别核验。

## 缓存 API 与持久化

路径相对于配置的缓存根地址：

- GET /notary/check?hash=&id=&owner=：立即查重，返回 passed / duplicate / pending_conflict、checkedAt、scope=indexed-records、两条链扫描状态。
- POST /notary/submit：仅接受 {location:{chainId,tx},record:签名声明}。限制 40,000 字节，验证结构和钱包签名；非透明声明不得含原件。立即保存待核验记录并返回状态，不等待 RPC。签名仅证明声明者控制钱包，历史容器所有权仍待链上核验。
- POST /notary/notify：兼容原 {chainId,tx} 通知，服务器自行回读声明。
- GET /notary/transaction/:chain/:tx：返回签名预览、独立核验后的 bundle（如有）、服务器 verification 状态和扫描快照。
- GET /notary/list?hash=&owner=&q=&sort=desc&page=1&pageSize=12：分页列表，区分 submission 和 bundle。pageSize 1–50，sort asc / desc。
- GET /health：notary.mode 为 cache-first-background-verification，附有效记录数、待核验数量、队列、扫描状态。

原子文件存储：notaries/ 仅存经过链上验证的证据；notary-submissions/ 单独存未经链上核验的签名声明；state/ 保存持久队列和扫描状态。预览不因重启被升级成已验证。24 小时仍未验证的提交不再参与公开待核验列表和临时查重，但保留详情与队列。链重组失效记录在详情标异常，不进入有效公证列表。

升级备份 bundle、替换并重启，保留数据目录及配置；既有合同不迁移。公开仓库不包含运营方凭据、私有 RPC 或真实用户证据。

## 测试

单元测试覆盖签名、隐私、块重建、缓存与队列重启、未验证预览隔离、并发重复声明、扫描时效、超时、重试、重组和异常状态。浏览器测试覆盖没有自动链上扫描的发布路径、图片分块、缓存离线/过期/重复、未知发送结果、刷新恢复不重发、通知重试、分页、服务器状态变化和手动独立核验。使用模拟钱包和链，不发送主网交易。
